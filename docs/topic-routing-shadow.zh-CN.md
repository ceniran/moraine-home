# 候选主题路由影子链路

这是一条候选箱前置的确定性建议链路，不是正式记忆分类器。主题相同只表示“值得放进同一批检查”，不证明属于同一事件，也不授权自动整合、分层、召回或推送。

第一阶段默认关闭。启用后，新候选仍照常写入正式候选箱；路由结果只写入独立的本机影子日志，并明确声明 `persisted_to_memory_store: false`。路由失败不会阻断候选入箱。

## 私密边界

- 主题定义文件与影子日志物理分离于记忆库，读取或写入后权限收紧为 `0600`。
- 导出、快照、正式审计事件、普通 API 和 MCP 都不包含主题定义、命中词、理由或影子结果。
- 已鉴权工作台还需第二枚 `MORAINE_PRIVATE_TOPIC_TOKEN`，才能访问 `/api/private/topic-routing/*`。
- MCP 只持有 `MORAINE_BETA_TOKEN`，即使知道私密端点地址也会收到 `403`。
- 隐藏对照组在人工选择前不返回路由结果，避免建议造成锚定；选择后才可用于对照核验。

## 主题文件

运行时私有文件不应提交到仓库。结构如下：

```json
{
  "topics": [
    {
      "topic_id": "synthetic-project",
      "name": "合成项目",
      "exact_terms": ["Project Cedar"],
      "aliases": ["雪松计划"],
      "supporting_terms": ["候选箱", "召回"],
      "veto_terms": ["不是雪松计划"],
      "version": "1"
    }
  ]
}
```

只保留真正被读取的字段。没有 `push_policy`、语义兜底开关、装饰性可见性字段或与记忆分层撞名的 `suggested_tier`。

## 匹配合同

- 输入先做 Unicode NFKC 和英文大小写折叠，不自动转换繁简体。
- 命中判断在规范化文本上完成，但 `matched_spans` 的起止位置映射回原始输入，可直接用于原文高亮。
- 中文专名按配置字面匹配；英文和数字词使用边界匹配。
- 最长词优先只在单个主题内部生效；不同主题独立扫描，不互相抢占同一段文字。
- 证据等级为 `exact > alias > supporting`，不把不同主题的原始总分相互比较。
- 多个 exact 是多主题；多个 alias 是歧义；仅有 supporting 时始终是歧义。
- `supporting_count` 只用于同证据等级内的稳定排序和调试，不升级证据等级。
- veto 只否决其所属主题，并优先于当前命中和继承。
- 继承不能独立创造命中；只允许辅助弱证据平局。新主题的 exact 命中会清除旧主题的继承贡献。

## 影子验收

分组只由 `candidate_id` 的稳定哈希决定，修改主题词表不会让同一候选换组；分析时再按独立保存的 `config_snapshot_id` 分层。可见组用于观察人如何回应建议；隐藏组才用于计算错归率和漏归率。影子日志只保存输入摘要、配置快照、路由输出、分组与人工最终选择，不保存第二份候选正文，默认保留 45 天。重复路由会追加新评估并保留旧选择，不覆盖历史。

## 同事件比较预览

工作台可通过同一枚私有能力令牌读取
`GET /api/private/topic-routing/event-matches`。该端点只比较仍在候选箱、且服务端已允许工作台看见主题证据的候选：

- 共同主题只负责打开比较门槛，不增加所谓“同事件分数”；
- 时间间隔只提供上下文，不能单独证明同一事件；
- `object_keys` 与 `action_keys` 必须由接入方显式提供，系统不从正文猜测；
- 对象或动作证据缺失会返回 blocker；身份、关系和边界类型永远保留人工复核 blocker；
- 返回值固定包含 `automatic_merge: false`、`persisted: false` 与可拆回声明；
- 端点不会改动候选的 `basket`，也不会改变定时入库条件。

因此无人值守入库不会等待人工一直在线，也不会抢在审核前自动合篮：尚未确认的候选仍分别通过原有准入判断；人工确认同一事件后，才由既有整合入口处理。

启用变量见 `.env.example`。本阶段仍不把主题建议接入整合执行、记忆分层、召回、自动唤醒或语义模型。
