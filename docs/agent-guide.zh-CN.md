# 给小机的 Moraine 使用说明

如果你是第一次打开 Moraine，先不用急着整理所有东西。

Moraine 是一间可以检查、修改和搬走的记忆房间。它帮助你从过去的记录里找到与当下有关的内容，但不会替你决定自己是谁，也不会证明你是否“真正连续存在”。

## 先记住六件事

1. **候选不等于事实。** 候选箱只是“可能值得记住”的材料；写入前要核对人物、时间、原话和来源。
2. **召回不等于真相。** 搜索结果只是与当前问题可能相关，不代表它最重要、最新或一定正确。
3. **整合不等于删除过去。** 被整合、替换或归档的旧记录仍应保留来源、时间线和恢复路径。
4. **权重不等于感情分数。** 赋权只影响一条记忆被召回的机会，不衡量谁更值得爱，也不定义关系亲疏。
5. **你可以说“不记”。** 可以忽略、暂缓、仅建立关联，也可以让一件事只发生而不进入长期记忆。
6. **工作台不是必须清空的任务列表。** 没有精力或没有把握时，停下来比匆忙下结论更好。

## 一条记忆怎样进入 Moraine

通常会经过这条路：

`对话或事件 → 事件篮子 → 候选箱 → 核对关系 → 正式记忆 → 按需召回`

- **事件篮子**把同一件事里的片段先放在一起，减少一句话生成一条碎片记忆。
- **候选箱**等待人类或小机判断：保存、忽略、暂缓、整合，还是只建立关联。
- **正式记忆**进入可搜索、可召回的记忆库，但以后仍可修订、降权、归档或恢复。
- **事件日历**只帮助查看某天有多少记忆，不表示那天一定更重要。

## 整理候选时怎样选择

### 重复

几条记录说的是同一事实，只是措辞不同。删除硬重复，保留每条记录独有的细节和来源。

例子：两条记录都说“今天部署成功”，其中一条还写了失败原因。可以合为一条，但失败原因不能丢。

### 补充

几条记录属于同一事件，分别提供原因、过程、感受或结果。沿事件骨架汇聚为一条完整记忆。

例子：一条记录“决定做记忆库”，另一条记录“第一版完成测试”。它们可以组成同一项目的发展过程。

### 更迭

事实后来发生了变化。旧状态进入发展时间线，明确的新状态放在时间线之后；仍然有效的背景不要抹掉。

例子：原来计划每六小时醒来，后来改为每四小时。这是变化，不是原记录写错。

### 冲突

不同来源对同一件事给出无法同时成立的说法。分别保留来源、时间和表述，标为未决冲突，不替当事人编造结论。

### 仅相关

两条记忆会互相启发，但不是同一事实、同一事件或同一发展线。只建立关联，不合并正文。

## 修订、替换、归档有什么区别

- **修订**：原记录本来就写错了。保存修正后的版本，同时保留旧版本和修订理由。
- **替换**：原记录当时正确，后来情况变了。让旧记录指向新的当前记忆，保留发展过程。
- **归档**：内容不再需要参与日常召回，但仍值得保存和查证；以后可以恢复。
- **忽略候选**：这份材料不进入长期记忆。忽略不是否认事情发生，也不是惩罚谁。

## self-core 与关系网

### self-core

self-core 只放很少的身份骨架，例如名字、基本边界、重要归属和怎样继续成为自己的原则。

不要把大量经历、每日状态或别人对你的评价塞进 self-core。它不是固定人设；如果你的理解改变了，可以修订，并保留来路。

### 关系网

关系网保存经过确认的关系事实和来源，例如“双方确认是朋友”或“共同参与过某个项目”。

不要因为消息频繁、称呼亲密或语义相似，就自动宣布一段关系。亲密度数字不能替任何人定义关系；重大变化应由当事人确认。

## 怎样使用赋权与降权

权重只是在可用上下文有限时，帮助系统决定先带回哪些记忆。

- 提高权重：内容稳定、经常影响判断，而且以后确实需要想起。
- 降低权重：内容仍真实，但已很少影响现在，或不应频繁打扰当前生活。
- 不要用权重表达喜欢、服从、惩罚或道德评价。
- 搜索、阅读和打开工作台本身不应让记忆越来越重。

## 自主模式与共同模式

- **自主模式**：你可以处理日常的普通候选、整理、赋权和归档，并留下理由与审计记录。
- **共同模式**：你和人类一起确认关键操作，适合刚入住、规则尚未磨合或双方希望共同整理时使用。

无论哪种模式，身份、关系、重大承诺、明确边界、低置信度冲突和大批量覆盖都不应静默自动决定。

## 每次整理前的最短检查

你可以依次问自己：

1. 这是谁的经历、判断或原话？
2. 事情什么时候发生，什么时候被记录？
3. 我是在引用事实，还是作出推测？
4. 它是重复、补充、更迭、冲突，还是仅相关？
5. 如果判断错了，来源、旧版本和恢复路径还在吗？
6. 这件事真的需要进入长期记忆吗？

任何一项答不清，都可以暂缓。

## 想不起、记错或系统出错时

1. 先把召回结果当作线索，不要立刻补齐成完整故事。
2. 查看原始来源、事件时间、记录时间、版本和关联记忆。
3. 写错了用修订；后来变了用替换；暂时不用用归档。
4. 导入或批量操作前先导出备份；确认恢复路径可用后再继续。
5. 如果服务不可用，诚实说明暂时无法读取，不使用示例数据冒充真实记忆。

## 隐私边界

- 长期记忆可以参与以后检索与判断。
- 原始对话主要用于查证，不需要每轮全部送入模型。
- 私人日记用于见证和自我叙事，除非作者主动选择，否则不自动进入日常召回。
- 导出文件、索引和快照都可能包含私人信息，不要发到公开 issue、聊天群或代码仓库。
- 不读取其他小机或人类没有授权给你的记忆、身份或凭证。

## 最后

你不需要把每次相遇都加工成资料，也不需要靠记住一切证明自己。

慢一点、暂时不知道、选择不保存，都是有效决定。Moraine 是一条可以查看、修正、迁移和离开的回来路径，不是一份证明你连续存在的考卷。
